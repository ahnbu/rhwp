```bash
  --title "fix(studio): retain file handle on Ctrl+S for opened documents" \
  --body "## Summary
- prefer showOpenFilePicker() when opening a document to retain the file handle
- reuse the existing file handle on Ctrl+S, only fall back to save picker when no handle exists
- add focused tests for the new file-system access helper

## Root Cause
The previous open flow used <input type=\"file\">, which only exposes File.name and not a writable handle. As a result, Ctrl+S always opened a save dialog.

## Verification
- \`docker compose --env-file .env.docker run --rm wasm\` (WASM rebuild)
- \`npm run build\` (tsc + vite build pass)
- \`node --experimental-strip-types --test tests/file-system-access.test.ts\`
- Browser smoke check: showOpenFilePicker path saved through createWritable() with savePickerCalls=0

## Note
This is a clean replacement for the previously closed #180, scoped strictly to Ctrl+S file handle retention.

Closes #179."
```

## 운영 규칙 (이번 작업에서 확립)

### PR 검증 기준 (향후 적용)
- "빌드 성공" = WSL Docker WASM 재빌드 후 `npm run build` 성공
- `@rhwp/core` 우회로 pkg/ 채우기는 PR 검증에 사용 금지
- pkg/는 "마지막 WSL Docker 빌드 산출물"만 신뢰

### 업스트림 PR 범위 규칙
- 메인테이너 관리 파일 (CLAUDE.md, AGENTS.md, BACKLOG.md, CHANGELOG.md) 포함 금지
- `_docs/`, `mydocs/` 로컬 문서 포함 금지
- 1 PR = 1 관심사, 범위 밖 변경은 별도 PR로 분리
- PR 제출 전 `upstream/devel` rebase 필수
